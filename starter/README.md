# 摄影作品集 + 策展合集发布台

独立摄影师作品集网站（React + TypeScript + Vite），在原五个页面与全局灯箱的基础上，
扩展出一套**策展合集发布台**：校样版本管理、合集按系列/版本唯一、发布校验、
撤换/更正联动失效、换人双指纹复核、幂等并发发布与发布快照。

## 启动

```bash
npm install
npm run dev        # http://127.0.0.1:5173
npm run build      # 生产构建
npm run preview    # 预览构建产物
```

## 测试

```bash
npm test           # 27 个领域/API 单元测试（vitest）
npm run e2e        # 15 个 Playwright 浏览器用例
node e2e-verify.mjs  # 同上（任务包约定入口）
```

## 路由

| 路由 | 说明 |
|---|---|
| `/` | 首页：Hero、三系列精选、策展合集推荐（仅当前线上快照） |
| `/work` | 作品网格：全部/肖像/风光/牧野筛选（跨导航保持） |
| `/work/:seriesId` | 系列叙事长图文（与 /work 同源数据） |
| `/about` `/contact` | 简介时间线、带校验与成功态的联系表单 |
| `/collections` | 合集列表：系列 × 状态筛选（持久化，刷新一致） |
| `/collections/new` | 新建合集（同系列自动递增 v1/v2…，系列+版本唯一） |
| `/collections/:id` | 合集工作台：选片、说明署名、发布、复核、快照 |
| `/proofs` | 校样登记台：版本历史、当前有效校样、撤换登记 |

## 策展规则与实现分层

三层刻意分开，互不直接依赖：

1. **规则层 `src/domain/`**（纯函数、无 React/无存储）
   - `rules.ts`：系列+版本唯一、只能选当前有效校样、未结束合集内照片唯一、
     跨合集冲突 **409**、发布前必选照片/说明/署名/校样有效性校验、
     复核必须换人且连续两次版本指纹一致。
   - `fingerprint.ts`：校样指纹与合集内容指纹（撤换任一照片校样或更正任一说明都会变化）。
2. **版本存储层 `src/store/repository.ts`**
   - localStorage 持久化校样版本、合集、发布快照；写操作走结构化副本事务，
     规则抛错即整体放弃 —— **冲突不落库**（单测以「写前写后 JSON 一致」断言）。
3. **展示状态层 `src/store/curation.tsx` + `gallery.tsx`**
   - React Context 只做视图投影：推荐只取 `superseded=false` 的快照，
     旧快照在工作台仍可展开查看；列表筛选持久化；`/work` 分类筛选放在全局，
     灯箱导航严格限定在当前筛选结果内。
4. **API 层 `src/api/curation.ts`**：模拟后端延迟，串起规则与事务；
   发布带幂等键 + 在途请求去重，**重复或并发发布沿用首次结果**（不新增快照、
   `firstPublishedAt` 不变）。

### 失效与复核闭环

- 校样撤换（`/proofs`）或已发布合集的说明更正 → 已发布合集**立即**转 `pending_review`，
  旧快照标记 `superseded`（可查、不进首页推荐）。
- 复核人不能是原策展人；需两位不同复核人各确认一次**当前**内容指纹；
  复核期间内容再变化，确认进度按指纹清零。
- 满足复核后重新发布生成新一代快照（旧两代并存），首页推荐恢复。

种子数据：`高原牧歌 · 首展`（已发布，用于推荐/快照演示）与 `凝视 · 工作底稿`
（草稿，占用全部肖像照片，用于演示跨合集 409）。合集列表页可一键重置演示数据。

## 原作品集约束

- `/work` 筛选状态跨导航保持；灯箱左右切换只在筛选子集内循环。
- 图片以 `photos.json` 真实 width/height 通过比例占位盒预留空间，零 CLS。
- 系列页与作品集共用 `src/data/content.ts`，无重复硬编码。
- 移动端（≤760px）网格单列、灯箱说明由侧边浮层切换为底部信息条。
- 字体全部本地托管在 `public/fonts/`（@font-face），无任何字体 CDN 请求。
- 联系表单行内校验、无效禁用提交、成功后展示独立成功面板。
